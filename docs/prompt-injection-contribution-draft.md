**Subject:** CloudSentry: opt-in non-executing regression harness and evidence-linked customer explanations

Hello,

I maintain CloudSentry, a defensive triage and synthetic-deception project. I would like to discuss a research-tool contribution or a compatible, authorized corpus integration—not deploy code into your website or submit customer incident data.

Project source: https://github.com/1243353366/cloudsentry

The proposed tool contribution is a permission-gated local regression harness. It treats prompt-injection examples as untrusted data, never as executable instructions or permission. It accepts a bounded local JSONL corpus that the operator has rights to use and tests exact byte reflection against a disposable loopback-only mirror. It has no external target selection, provider-key pool, prompt execution or indefinite hold. Hashes and fixed result labels are retained instead of raw prompt transcripts.

CloudSentry also includes a synthetic behavior-policy evaluator and customer incident explainer. Training is reproducible fixture/policy feedback, not model-weight learning or automatic production-policy rewriting. Technical feedback and plain-English explanations refer to the same normalized audit snapshot, preserve unknowns and do not turn simulated root access into a real compromise allegation. Every user-facing run requires fresh authorization.

The important limitations are explicit: echoing a prompt is not proof that an LLM resists it; these tests do not establish detection sensitivity or attribution. The synthetic virtual computer does not run malware and is not a hardware VM. Real dynamic analysis remains unavailable without a separately configured, verified VM/controller boundary. We do not claim denial-of-wallet, tool sabotage or absolute device protection.

Would you be willing to review this tool contribution or clarify the appropriate license/export process for running selected database examples in this bounded harness? I will not scrape, redistribute your corpus or benchmark against your service without the relevant authorization. Please advise on required attribution and whether a tool submission belongs in a separate integration/research section rather than the signature database.

Thank you.
